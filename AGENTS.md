# 🤖 btools — Инструкции для ИИ-Агентов и Разработчиков

> **Важно:** Данный документ является обязательным регламентом для всех ИИ-агентов (AI coding agents) и разработчиков, работающих в репозитории `btools`.

---

## 1. Регламент версионирования (Strict Tenths Versioning)

Все релизы и теги в репозитории `btools` должны следовать **строгой схеме версионирования до десятых**:

```
1.0  ->  1.1  ->  1.2  ->  ...  ->  1.9  ->  2.0  ->  2.1 ...
```

- ❌ **Запрещено:** Использовать трехкомпонентные версии (например, `1.0.1`, `1.2.4`, `1.0-patch`).
- ✅ **Разрешено:** Только одна значащая цифра после точки: `1.0`, `1.1`, `1.2`, ..., `1.9`, затем строго переход на `2.0`.
- Для промежуточных пре-релизов допускается суффикс типа `1.0-alpha`, `1.0-beta`, `1.0-rc`, но базовый номер версии строго сохраняет формат десятых.

## 2. Обязательный протокол каждого коммита и пуша (Git Commit & Push Protocol)

Каждый коммит/пуш в репозиторий `btools` ОБЯЗАН содержать:

1. **Детальное текстовое описание:**
   - Четкий заголовок с указанием версии.
   - Список решенных задач, исправленных багов и добавленного функционала.
   - Изменения в шейдерах или архитектуре.
2. **Графические скриншоты инструментов (Visual Verification):**
   - Ни один релиз или пуш не принимается без свежих графических скриншотов работающих инструментов (`docs/screenshots/`).
   - Скриншоты должны демонстрировать:
     - Основной вид и работу `ring-slider` (включая активные шейдерные режимы: Threads, Pixel, Liquid).
     - Работу `slider` (Slider Mockup Studio).
     - Хаб инструментов `index.html`.
3. **Фиксация в CHANGELOG.md:**
   - Перед каждым коммитом в файл `CHANGELOG.md` добавляется блок с описанием текущей версии, датой, списком изменений и ссылками на скриншоты.

## 3. Архитектурные принципы и ограничения btools

1. **Запрет деформации 3D-геометрии слайдов (Rigid Mesh Rule):**
   - Интерактивный обруч (гизмо) отвечает **ТОЛЬКО** за область активации шейдерного эффекта на экране.
   - Меши 3D-слайдов ни при каких обстоятельствах не должны искривляться, вытягиваться или деформироваться геометрически обручем.
2. **Прозрачность и глубина WebGL (Transparency & Depth Buffer):**
   - На всех шейдерных материалах со стиранием и полупрозрачностью (`transparent: true`) устанавливать `depthTest: false` и `depthWrite: false`.
   - Это гарантирует отсутствие темных обводок, артефактов сортировки прозрачности и белых линий на стыках.
3. **Чистый фейд в фон (Zero Halo Fade):**
   - При активации «Фейд в фон» альфа-канал за пределами зоны действия маски обязан плавно и гарантированно уходить в `0.0`.
   - Спекулярные блики нитей/пикселей обязаны затухать синхронно с маской, не оставляя белых штрихов в фоне.
4. **Унифицированная поддержка форм (Gizmo Shapes):**
   - Любой инструмент с радиальным эффектом должен поддерживать 4 формы области:
     - `ellipse` — свободный эллипс;
     - `circle` — ровный круг (1:1);
     - `rect` — прямоугольник (свободный / Shift для квадрата);
     - `square` — строгий квадрат (1:1).
   - Внутри области поддерживается ресайз безопасного чистого ядра фокуса (`uInnerRatio`).
5. **Масштаб колебаний (Wobble):**
   - Диапазон бегунка колебаний во всех шейдерных режимах составляет `0.0 .. 10.0`.

- [ ] Код протестирован в браузере (0 ошибок в консоли, 0 WebGL-варнингов).
- [ ] Все 4 формы зоны (Овал, Круг, Прямоугольник, Квадрат) проверены.
- [ ] Сделаны скриншоты и сохранены в `docs/screenshots/`.
- [ ] Обновлен `CHANGELOG.md` с фиксацией версии по схеме десятых (`1.X`).
- [ ] Сообщение коммита содержит развернутое описание изменений.
